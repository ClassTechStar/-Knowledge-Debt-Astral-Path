## 2. 逐项改造

### P5 密钥信封：轮换与失效提示（C# + 前端）

**C#（`src/AstralPath.Core/Agent/KeyEnvelope.cs` 重写、`MimoConfigResolver.cs` 重写）**

- 信封结构升级 `v2`：`Version` + `KeyId` + `Fingerprint()`（密文 SHA-256 前 8 字节十六进制）。旧版无 `KeyId` 的信封仍可解析（兼容路径有测试看守）。
- `Rotate(env, oldDek, newDek)`：用旧 DEK 解出明文 → 新 DEK 重新封存；信封不可读时返回 `null`（不制造"看起来成功"的假象）。
- `EnvelopeIssue` 枚举：`None` / `DekMissing` / `Revoked` / `Unreadable`，`IKeyRevocationList` + `InMemoryKeyRevocationList` 实现按 `KeyId` 吊销。
- `MimoConfigResolver` 把三种失败原因连同 `UserMessage` 一起报出，吊销判定优先于其它错误——用户看到的是「自定义密钥需重新配置」而不是静默切回演示密钥。

**前端（`deploy/monolith-web/index.html`）**

- `window.__AP_REVOKED__=[]`：发布方把泄露信封的 `KeyId` 写进这个数组即可作废，无需接触用户本机 DEK。
- `getConfig()` 先读信封，命中吊销/缺 DEK/不可读时经 `__apEnvIssue()` 上报；`saveConfig()` 写 `{v:2, kid, fp}`；`renderStatus()` 把原因显示在「账户」页状态行。

**测试**：`tests/AstralPath.Core.Tests/KeyEnvelopeRotationTests.cs` 8 例——封版本+指纹、新旧 DEK 轮换、不可读时轮换返 null、吊销、缺 DEK、篡改密文→Unreadable、旧信封兼容、无信封走内置。

### P6 state 分片 + IndexedDB（`shared/store.js` + 页面接线）

**分片模型**（UMD，浏览器 `window.APStore` / Node `require`）：

| 分片键 | 承载 | 写频 |
|---|---|---|
| `ap:meta` | user/consent/optOut/activeBookId/day/userName/kgMode/onboard/planMeta/chat **+ 一切未登记新键** | 低 |
| `ap:books` | books[] 章节骨架（大文本已在 IndexedDB，只留索引） | 切书时 |
| `ap:answers` | mastery/logs/debtExplain | **每次作答** |
| `ap:plan` | plan/sale | 计划变更时 |
| `ap:papers` | papers[] 试卷识别结果 | 识别时 |

- `write()` 带 `part→json` 缓存，**只写内容变化的分片**；写失败的分片保留旧缓存下次重试。
- 迁移：首读发现旧单键 → `backup()`（`ap:backup:<ts>`，仅留最新一份，同毫秒撞键自动追加序号）→ 写分片 → 成功后删旧键。回退路径始终存在。
- `read()` 把「JSON 可解析但非对象」（如字面量 `null`）判为缺失——这是黄金用例 ST-09 抓出的真实缺陷。
- 页面接线（`load()/save()/btnWipe/首访检测`）：分片优先；无有效分片走旧键并一次性迁移；**残缺分片**（如历史上 books 写失败）合并可读分片交 `migrate()` 补默认值，不用默认态覆盖已落盘的 mastery/logs；`save()` 失败时留痕 `APDiag` → 丢冗余备份 → 强制全写重试一次 → 仍失败则顶栏显式报警。

**量化**：一次作答从「重写整包」变为「只重写 `ap:answers`」。黄金用例 ST-08 用 4.5MB 试卷状态验证 `meta` 分片保持 227 B、`papers` 承载主体且完整往返。

**门禁**：`scripts/store_runner.js`（Node + FakeLS）10 例 → `scripts/verify_store.py`（跑黄金用例 + 校验页面真的调用了 `APStore.read/write/clear`，防"模块写好没接上"）→ 进 `verify_all.ps1` 与 CI。

**浏览器级冒烟**（CDP，Edge headless 155 + 真实单体页）：首访横幅出现 → 写入旧单键后 `load()` 完成迁移（5 分片 + 1 备份、旧键删除）→ 二次 `load()` 走分片路径数据一致 → 只改 logs 时仅 `ap:answers` 重写（books/meta/plan 字节不变）→ 损坏 `ap:books` 后 `load()` 保住 34 键 mastery 与 logs、books 以默认样本补齐。启动零错误（`APDiag.count()=0`）。

### P13 空 catch 分类处置 + 错误可观测

- **C#**：新增 `src/AstralPath.Core/Diagnostics/Diag.cs`（编译器注入 `[CallerMemberName]`/`[CallerLineNumber]` 的环形缓冲，最新在前，`Snapshot()`/`Total`）。约 40 处真正空 catch 全部改为 `Diag.Recover(ex, note)` 或带降级动作；`/health/ready` 增补 `diagnostics.errorsTotal` 与最近 5 条。
- **门禁**：`scripts/verify_no_empty_catch.py` 判空/仅注释 catch 体即红（`Diag.cs` 自身在 ALLOW 名单），当前 181 个 `.cs` 全过；`.editorconfig` 把 CA1031 降为 `suggestion`——真门禁是语义检查而非告警刷屏。

### P12 前端构建合并（`build-frontend.ps1` 取代手工三镜像）

- `scripts/gen_frontend_regions.py`：把 `shared/` 的符号/模块刷新进 index.html 的 `/* AP:BEGIN <id> · DO NOT EDIT */` 生成区（括号配对抽取 + 按标记行缩进重排 + 行尾样式还原）。`--check` 为内容门禁。
- 本次落地 5 个生成区：`safe-dom.js#esc`（全局）、`core.js#removeCyclesTopo`、`core.js#normalize`、`core.js#parseJsonLoose`（MiMo IIFE 内）、`shared/store.js`（整模块，独立 `<script>`）。
- **删除** T11 IIFE 里的第三份私有 `esc`（改用全局生成区版本）——这是前端共享逻辑重复的最后一处。
- `shared/safe-dom.js` 的 `esc` 改为自包含（映射表内联），按符号抽取后不依赖模块级变量；XSS 黄金用例 14 例复跑全绿证明行为不变。
- `scripts/build-frontend.ps1`：`刷新生成区 → sync-monolith-html.ps1 三镜像 → hash 报告`；`-Check` 模式进 `verify_all.ps1`（新步骤 `frontend-regions`）与 CI。**有意不自动重建单文件产物**——md5 基线重打是显式动作，防"悄悄换基座"。
