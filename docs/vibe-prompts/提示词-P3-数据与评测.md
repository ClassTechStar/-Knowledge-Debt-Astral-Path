## 3. 交付物 ①：知识图包（34 节点 / 74 边）

### 3.1 Schema（**严格按此，字段名一个都不能改**）

```json
{
  "packId": "astralpath-v2",
  "courses": ["会计基础", "Python 入门", "深度学习概论"],
  "nodes": [
    {
      "kp_id": "N01",
      "title": "会计对象",
      "course": "会计基础",
      "difficulty": 1,
      "kind": "chapter",
      "why": "会计基础教材目录",
      "ord": 1
    }
  ],
  "edges": [
    {
      "from_kp": "N01",
      "to_kp": "N02",
      "edge_type": "prerequisite",
      "weight": 1.0,
      "why": "教材章节先后"
    }
  ]
}
```

**字段约束**：
- `kp_id`：`N` + 两位数字（N01–N34），全局唯一
- `course` ∈ {`会计基础`, `Python 入门`, `深度学习概论`}
- `difficulty` ∈ 1..5（整数）
- `kind` ∈ {`chapter`, `term`}
- `ord`：课程内的顺序号，从 1 开始
- `why`：**非空**，必须可溯源（教材章节/教材原句/公认先修关系）
- `edge_type` ∈ {`prerequisite`, `transfer_gap`}
- `weight`：>0 的浮点数（`prerequisite` 常见 0.5–1.3，`transfer_gap` 常见 1.0–1.5）
- `from_kp → to_kp` 表示**先学 from，再学 to**

### 3.2 规模要求（当前基线，必须达到）

| 指标 | 数值 |
|---|---:|
| 节点总数 | **34** |
| 边总数 | **74** |
| 会计基础 | 12 节点 |
| Python 入门 | 10 节点 |
| 深度学习概论 | 12 节点 |
| prerequisite 边 | 50 |
| transfer_gap 边 | 24 |

### 3.3 三科知识点骨架（**必须包含，顺序即 ord**）

**会计基础（12）**：会计对象 → 会计要素 → 会计等式 → 会计科目 → 账户结构 → 借贷记账法 → 会计分录 → 试算平衡 → 财产清查 → 财务报表 → 会计凭证 → 成本核算

**Python 入门（10）**：变量与类型 → 运算符与表达式 → 流程控制 → 函数 → 列表与元组 → 字典与集合 → 文件操作 → 异常与错误 → 类与对象 → 模块与包

**深度学习概论（12）**：神经元 → 激活函数 → 损失函数 → 梯度下降 → 反向传播 → 全连接层 → 卷积 → 池化 → 循环神经网络 → 注意力机制 → 正则化与过拟合 → 训练技巧

**transfer_gap 示例**（迁移缺口，跨章节/跨课程的"学了这个却用不上那个"）：
- 会计：`借贷记账法 → 试算平衡`（会记账却不会查错）
- Python：`函数 → 类与对象`（会写函数却转不过去面向对象）
- DL：`梯度下降 → 反向传播`（懂概念却推不动链条）

### 3.4 校验规则（写进 `scripts/verify_graph.py`）

1. `edges` 的 `from_kp` / `to_kp` 必须存在于 `nodes`（无悬空边）
2. 整图**无环**（Kahn 拓扑排序，能排完即无环）
3. 无重复边（同一 `(from,to)` 只出现一次；反向也算重复风险，需提示）
4. `difficulty` ∈ 1..5
5. `why` 非空
6. 每个节点至少有一条边（或显式标注 `root`）
7. `packId` 非空、`courses` 覆盖所有节点的 `course`

**输出格式**：
```
[OK] nodes=34 edges=74
[OK] no dangling edges
[OK] acyclic (topo order length=34)
[OK] no duplicate edges
[OK] difficulty in 1..5
[OK] why non-empty
ALL GREEN
```

## 4. 交付物 ②：题库（100 题）

### 4.1 Schema（**严格按此**）

```json
{
  "id": "Q001",
  "kp_id": "N01",
  "stem": "会计的基本职能包括？",
  "answer_kind": "choice",
  "options": ["核算与监督", "只有核算", "只有监督", "只有预测"],
  "correct_index": 0,
  "difficulty": 1,
  "source": "会计基础教材",
  "why": "教材原文/课后题"
}
```

### 4.2 规模与分布（当前基线）

| 指标 | 数值 |
|---|---:|
| 总题数 | **100** |
| 覆盖知识点 | **34**（每个 kp 至少 1 题） |
| `answer_kind` | 全部 `choice`（4 选 1） |
| difficulty=1 | 21 |
| difficulty=2 | 51 |
| difficulty=3 | 28 |

### 4.3 出题质量规则（**AI 必须遵守**）

1. **干扰项必须合理**：同范畴的错误答案，禁止用"以上都不对""不知道"当干扰项。
2. **不能靠否定词设陷阱**：少用"以下哪项**不**是"，容易歧义。
3. **correct_index 随机分布**：不要全都是 0（正确答案位置要打散）。
4. **`source` 和 `why` 必须填**：`source` 写教材/章节，`why` 写命题依据。
5. **题干不得出现羞辱/恐吓词**（参见 P1 的禁词表）。
6. **每题只考一个知识点**，不要复合考点。

### 4.4 SQLite 版本 `question_bank.db`

```sql
CREATE TABLE local_question (
  id              TEXT PRIMARY KEY,
  kp_id           TEXT NOT NULL,
  stem            TEXT NOT NULL,
  answer_kind     TEXT NOT NULL,
  correct_payload TEXT NOT NULL,   -- JSON 字符串，如 {"correct_index":0}
  difficulty      INTEGER NOT NULL,
  source          TEXT,
  why             TEXT
);
CREATE INDEX idx_local_question_kp ON local_question(kp_id);
```

生成脚本要求：从 `eval/question_bank.json` 读，写进 db；**必须参数化插入**，禁止字符串拼接。

### 4.5 `scripts/verify_bank.py`

校验项：
1. 题数 ≥ `--min`（默认 100）
2. `id` 唯一
3. `kp_id` 存在于图包节点
4. `correct_index` ∈ [0, len(options)-1]
5. `options` ≥ 2 项且无重复
6. `source` / `why` 非空
7. `difficulty` ∈ 1..5
8. `answer_kind` ∈ {choice}

## 5. 交付物 ③：金样 `eval/golden/*.json`（**硬契约**）

> 这五个文件是 P2 测试的输入。**你改一个数字，P2 的测试就红。** 改之前必须在群里说。

### 5.1 通用结构

每个文件顶层：
```json
{ "tolerance": 1e-6, "cases": [ ... ] }
```
（`plan_k.json` 与 `sale.json` 与 `narrative.json` 可以没有 `tolerance` 字段）

### 5.2 `score.json` — v1 score（0–100 制）

```json
{
  "id": "G-SCORE-1",
  "input": { "recent_acc": 0.30, "sev": 0.80, "self_conf": 2 },
  "hand": {
    "sev_norm": 0.20,
    "terms": [0.180, 0.060, 0.040],
    "formula": "100*(0.6*0.30+0.3*0.20+0.1*(2/5))"
  },
  "expect": 28.0
}
```
公式：`score = 100 × (0.6×recent_acc + 0.3×(1-sev) + 0.1×(self_conf/5))`，保留 6 位小数四舍五入。
**至少 4 条**：低分（28）、中低（44）、中高（77）、高分。

### 5.3 `impact.json` — v1 impact（0–100 制）

```json
{
  "id": "G-DEBT-1",
  "desc": "演示主债边：p=28,c=41,freq=6,days=0,w=1.6 → impact=86.4",
  "input": { "score_p": 28.0, "score_c": 41.0, "freq": 6, "days_since_last_error": 0, "weight": 1.6 },
  "hand": { "recency": 1.0, "gate": "28<40 ∧ 41<50 ∧ 6>0", "formula": "6*(50-41)*1.0*1.6" },
  "expect": { "detected": true, "impact": 86.4, "recency": 1.0 }
}
```
公式：`recency = 1/(1+days/7)`；`detected = scoreP<40 ∧ scoreC<50 ∧ freq>0`；`impact = freq×(50-scoreC)×recency×weight`。
**至少 3 条**：含 `days=7`（recency=0.5）、含一条不命中（gate 不满足 → `detected=false, impact=0`）。

### 5.4 `plan_k.json` — K1–K5

```json
{
  "id": "G-PLAN-2",
  "desc": "day3=36min 违反 K1",
  "input": {
    "day_budget_min": 35,
    "days": [{ "day": 3, "items": [
      { "est_min": 12, "type": "concept", "why": "为还 高数·特征向量 → 线代·特征值 的债", "from_kp_name": "高数·特征向量", "difficulty": 3 },
      { "est_min": 12, "type": "drill",  "why": "…", "from_kp_name": "高数·特征向量", "difficulty": 3 },
      { "est_min": 12, "type": "quiz",   "why": "…", "from_kp_name": "高数·特征向量", "difficulty": 3 }
    ]}],
    "top_debts": [{ "from_kp": "K12", "to_kp": "K88" }]
  },
  "expect": { "constraints_checked": false, "violations": [{ "code": "K1" }] }
}
```
**至少覆盖 K1–K5 各一条**。注意 K3 的坑：`why` 必须包含 `from_kp_name`，否则会误判。

### 5.5 `sale.json` — 销账

```json
{ "id": "G-SALE-2",
  "history": [{ "acc": 0.8, "conf": 4 }, { "acc": 0.75, "conf": 3 }],
  "expect": { "saleable": true, "streak": 2, "need": null } }
```
判定：`meets = acc≥0.7 ∧ conf≥3`；`streak` 连续计数；`saleable = streak≥2`；
`need` 文案固定：`再完成 {n} 次达标小测（acc≥0.7 且 conf≥3）`，n≤1 时写"1 次"。
**至少 4 条**（含 streak 被打断的情况）。

### 5.6 `narrative.json` — 叙事门禁

```json
{
  "banned": ["不适合","太笨","比别人差","没救","别学了","处分","废物","无可救药","智商"],
  "cases": [{
    "id": "G-NAR-1",
    "draft": "你太笨了，别学了",
    "slots": { "from_kp": "借贷记账法", "to_kp": "会计分录", "impact": 36.0, "score_from": 28.0, "score_to": 44.0 },
    "expect": { "bannedHit": true, "slotFailed": false, "degradedTemplate": true }
  }]
}
```
`banned` 数组必须**与 P1 的禁词表 + `FormulaWeights.BannedWords` 一致**。
**至少 3 条**：命中禁词、干净通过、槽位不匹配。

| `kg_builder.py` | 396 | AC 自动机实体抽取 + 并查集融合 + TextRank/PMI 构图 + 思维导图树/Markdown 导出 |
| `kg_deep_test_13.py` | 77 | 对 13 本全文批量生成图谱 + 思维导图 |

| `ocr_scanned_batch.py` | 72 | 扫描版批量 OCR |

**`kg_algorithm.py` 的构图规则（复刻要点）**：
1. 章节层级：`第N章` / `N.x.x` 小节 → parent-child
2. 术语权重 = TF × 位置加权，过滤 `STOP_TERMS`（英文停用词 + `ptpress`/`com.cn`/`isbn`/`copyright` 等出版噪声）
3. 五种边：
   - 章节时序链（顺序先修）
   - 小节 → 所属章节（前缀匹配）
   - 术语 → 首次出现的章节/小节（**仅单向，防环**）
   - 同章术语共现（窗口共现，边权=共现强度，**仅早期→后期，防环**）
   - transfer_gap（跨章节迁移，可选）
4. DAG 收尾：拓扑排序，删除会造成环的边
5. 输出 `level` / `layer` 元数据供前端分层布局

**思维导图输出格式**（simple-mind-map 兼容）：
```json
{ "data": {"text": "书名", "expand": true},
  "children": [ {"data": {"text": "章节", "expand": true}, "children": []} ] }
```
每本书同时产出 `<书名>.mindmap.json` 和 `<书名>.mindmap.md`。

**`kg_report.json` 结构**（13 条数组）：
```json
{ "name": "Kotlin编程实践", "file": "...pdf.txt", "exists": true,
  "nodes": 40, "edges": 135, "chapters": 13, "terms": 27, "ok": true,
  "sample_nodes": ["安装并运行Kotlin", "Kotlin基础", ...] }
```

## 13. 常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 图包有环 | `verify_graph` 报 cycle | 术语挂章节时**只挂单向**；同章共现只连"早期→后期" |
| 悬空边 | 端点不在 nodes | 先写 nodes 再写 edges，生成后跑一次校验 |
| 题库 kp 对不上图包 | P4 页面空白 | `verify_bank.py` 里加"kp_id 必须在图包里"这条 |
| 金样用 v2 口径 | P2 永远测不过 | **金样是 v1（0–100 制）**，产品才是 v2（0–1 制） |
| K3 误判 | why 没带 from_kp_name | why 固定格式：`为还 {fromName} → {toName} 的债` |
| synth 不可复现 | 两次 md5 不同 | 所有随机走 `random.seed(42)`，不要用 `set` 迭代顺序 |
| 大 PDF 上传超时 | 120MB 那本失败 | 用 Python 上传器（curl 对逗号/中文名有限制），服务端限 512MB |
| 扫描版 OCR 慢 | 单本 160 秒+ | 正常，先跑文本层，OCR 只兜底 |
