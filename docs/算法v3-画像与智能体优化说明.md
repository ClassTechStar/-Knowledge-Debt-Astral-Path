## 二、用户画像：逐个说清

### P1 · 波动率没按正确率归一化（最隐蔽）

**v2**
```csharp
var flips = 0;
for (var i = 1; i < list.Count; i++)
    if (list[i].Correct != list[i - 1].Correct) flips++;
var vol = (double)flips / (list.Count - 1);
```

问题：**翻转率的期望值本身就随正确率变化**。一个正确率恰好 0.5、作答接近随机的学生，
期望翻转率就是 `2×0.5×0.5 = 0.5`；而正确率 0.9 的正常学生期望只有 `2×0.9×0.1 = 0.18`。

于是 v2 会把 **acc≈0.5 的正常学生一律判成"波动大"**（`SoftNudge` 里 `Volatility > 0.6` 直接触发），
而真正"忽上忽下"的高正确率学生反而可能不触发。

**v3**：
```csharp
var expectedFlip = Math.Max(2 * acc * (1 - acc), 0.05);
var excess = vol / expectedFlip;   // >1 才是真的比随机更抖
```
`Volatility` 原始值保留（契约），新增 `ExcessVolatility`；`Style.Steady` 与 `SoftNudge` 都改用它。

### P2 · 只有单一 Brier，定位不了问题

Brier 会把"高信心答对"和"低信心答错"平均成一个好看的数字。
**v3** 新增 `CalibrationCurve`（按信心 1–5 分桶，给出每档 MeanConf / Accuracy / Gap）与 `Ece`（期望校准误差）。

测试 P32：一个**全部答对但一律只报 3 分**的学生 —— Brier 只有 0.16（看起来还行），但 ECE = 0.4，
一眼看出是**系统性低估自己**。v2 完全看不出这件事。

### P5 · 主题兴趣：时间不衰减 + 难度因子形同虚设

**v2**
```csharp
var interest = (double)n / total;
var weight = gap * (0.4 + 0.6 * interest)
           * (0.5 + 0.5 * (1 - Math.Abs(diff - 0.5)));
```

第二个因子：`diff=0.5` 时 =1.0，`diff=0` 或 `1` 时 =0.75 —— **取值域只有 [0.75,1.0]，25% 的幅度**，
注释说"难度适中 → 值得练"，实际几乎不区分。

而且 `n/total` 无时间衰减：**三个月前猛练过的知识点，今天还排在推荐第一位**。

**v3**：兴趣带指数时间衰减（默认半衰期 14 天）；难度因子改成峰值在 0.55 的目标难度曲线，
取值域扩展到 [0.35,1.0]，真正起作用。
测试 P33：5 次 30 天前的作答 vs 2 次今天的作答，**v2 排前者、v3 排后者**。

### P6 · 把"标签个数"叫成 k-匿名（概念误用）

**v2**
```csharp
if (safe.Count < k) return (Array.Empty<TagOut>(), true);   // k 是标签个数！
return (safe.OrderByDescending(t => t.Weight).ToList(), false);
```

k-匿名（k-anonymity）指的是**该标签覆盖的群体人数 ≥ k**，不是"至少显示 k 个标签"。
而且 v2 是**一抑全抑**：一个标签样本不足，整个视图全部清空，粗粒度且没用。

**v3**：
- 旧重载保留（改名为"最少标签数"，注释正名），不破坏既有调用
- 新增 `TeacherViewAnonymized(tags, cohortCountByTag, k)`：**逐个标签**判断覆盖人数，不足则抑制该标签；
  禁列域（sensitive/crisis/semantic）永不外发

测试 P34：cohort=10 的标签可见，cohort=2 的被抑制，crisis 域被抑制 —— 三者互不牵连。

### P7 · 伪 Laplace 不满足差分隐私（最严重）

**v2**
```csharp
var u = Math.Abs(Math.Sin(value * 12.9898) * 43758.5453) % 1.0;
var sign = u < 0.5 ? -1.0 : 1.0;
var mag = -Math.Log(1 - u) * sensitivity / epsilon;
return value + sign * mag;
```

三个问题：
1. **同一个 `u` 既决定符号又决定幅度** —— 二者强相关，合成分布严重偏离 Laplace
2. **哈希基于 `value`** —— 同一个值永远加同样的噪声。攻击者只要多观察几次就能反推真实值，
   **这不是差分隐私**（DP 要求噪声独立于数据）。而且哈希用的是经典 GLSL `sin-hash`，低比特规律性很强
3. 没有值域裁剪，可能输出负数或越界值

**v3**：标准 Laplace 逆变换 `x = -b·sgn(u-0.5)·ln(1-2|u-0.5|)`，`b = sensitivity/epsilon`；
噪声由 `seed` 驱动（**与 value 无关**）；支持 `min`/`max` 裁剪；相同 `(seed, value)` 仍可复现。

测试 P35 直接断言 `noise(0.5) - 0.5 == noise(0.9) - 0.9` —— **噪声与 value 无关**，
这一条就是 v2 通不过的。

> 注：默认 `seed=0` 仅为可测。真实部署必须每请求传入随机 seed，否则固定噪声同样不具备 DP 语义。

### P8 · 软提示判据

**v2**：`Accuracy < 0.35 && MeanConf > 0.6` —— 用**绝对信心**判过度自信。
**v3**：改用 `CalibBias > 0.25`（信心 − 实际正确率），并新增"连续答错 ≥3 → 回先修"的提示。
测试 P36：确实会且信心高的学生（acc 0.9 / conf 5）不再被误判。

## 三、智能体：逐个说清

### A1 · 三个常量定义了却从未使用（最刺眼）

```csharp
public const double TauExec = 0.75;
public const double TauClarify = 0.60;
public const int MaxClarify = 2;
...
if (best is not null && bestScore >= 0.5)   // ← 实际用的是硬编码 0.5
```

`TauExec` / `TauClarify` / `MaxClarify` 在整个 `Classify` 里**一次都没被引用**。
注释还写着"分数不足阈值时仍 execute，但标记低置信" —— 这个分支根本不存在。

**v3**：三个常量全部启用，并加入「最优与次优差距 < 0.08 → 判为歧义，先问一句」。

### A2/A3 · 打分只取最高锚点，且与句子无关

**v2**
```csharp
var s = 0.55 + Math.Min(0.45, a.Length / 12.0);
if (s > hitScore) { hitScore = s; hitAnchor = anchor; }   // 只保留最高
...
if (best is not null && bestScore >= 0.5)
```
两个毛病：
1. **多锚点同时命中不加分** —— "生成复习计划安排"同时命中"复习计划"和"计划"，证据明显更强，却没体现
2. 分数**只取决于锚点长度**，与句子长短无关 → 一句 30 字的话里偶然出现"条件"两字，
   也算 0.72 分 ≥0.5，直接 execute

**v3**：
```csharp
var score = maxS + 0.5 * Math.Min(sumOthers, 1.0);              // 多锚点饱和累加
score += 0.15 * Math.Min(1.0, matchedLen / Math.Max(6.0, norm.Length)); // 覆盖率奖励
```
测试 A34：单说"计划"得 ~0.63，说"生成一个十四天的复习计划安排"涨到 ≥`TauExec`。

### A4 · 负例快落误杀正常请求

**v2**：`if (_negative.ContainsAny(norm)) return fallback;`
`_negative` 里有 `"好的"`、`"ok"`、`"随便"` —— 用户说 **"好的，帮我生成计划"** 会被整句判死，
请求直接吞掉，用户只看到兜底话术。这是非常影响体验的真 bug。

**v3**：要求负例**占整句 ≥60%** 才算客套：
```csharp
var ratio = (double)longest / norm.Length;
if (ratio >= 0.6) → fallback
```
"ok"（ratio 1.0）→ 兜底 ✓；"好的，帮我生成计划"（ratio 0.22）→ 正常路由到 `plan.create` ✓

### A5 · 槽位填充永不收敛（死循环）

**v2**
```csharp
if (!string.IsNullOrWhiteSpace(awaitingIntent))
    return new AgentRouteResult(intent.IntentId, 1.0, "clarify", intent.RequiredSlots, "R1:awaiting_slot");
```
只要调用方传了 `awaitingIntent`，**无条件返回 `clarify`** ——
槽位永远填不完，`MaxClarify` 也没检查，用户可以无限被追问。

**v3** 四处修复：
1. **抽槽**：两级启发式 —— ①槽位名出现；②残余法（剔除锚点与口语填充词后仍有实质内容，且只剩一个槽位未填 → 该残余即它的值）
2. 槽位齐了 → `execute`
3. `clarifyCount >= MaxClarify` → 停止追问，按已有信息 execute
4. 允许**中途换话题**（新意图分数 ≥ `TauExec` 就切换）

> 抽槽这条我自己第一版也写歪了：只认槽位**名**，用户说"检索 会计基础"（给的是**值**）照样追问。
> 测试 A35 直接把这个场景钉住了。

### A6 · 无多轮上下文

"再解释一下"这种省略指代，v2 完全无法处理（每次独立分类，分数又不够高 → 掉回兜底）。
**v3** 新增 `prevIntentId` 参数：若当前最佳意图与上文一致，**门槛从 `TauExec` 降到 `TauClarify`**；
分数仍不足时直接用上文意图兜底。测试 A39。

### A7 · 角色位图的 32 位上限

**v2**：`1u << (it.Bit % 32)` —— 取模意味着 bit 32 与 bit 0 共用同一位，意图超过 32 个就错配。
且每个意图都要 `Split(',')` 一遍字符串。
**v3**：构造时预建 `Dictionary<role, HashSet<intentId>>`，无上限、无重复解析。
