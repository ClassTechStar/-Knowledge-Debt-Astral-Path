## 2. 架构形态对比

```
基准（-Knowledge-Debt-Astral-Path）              源目录（Astralpath）
┌──────────────────────────────┐          ┌──────────────────────────────┐
│ deploy/k8s（10 个微服务）      │          │ 单 HTML（17.3MB 自包含）      │
│ ├ concept-diffusion-svc       │          │ ├ 业务逻辑（index.html 内联）  │
│ ├ exam-impact-svc             │   ──►    │ ├ OCR 引擎（tesseract+pdf.js）│
│ ├ knowledge-forecast-svc      │  演进为  │ ├ AI 云桥 __AP_MIMO__         │
│ ├ learning-velocity-svc 等…   │          │ └ 内置演示密钥（AES-GCM）     │
│ src/AstralPath.*（C# 15 项目）│          │ 零后端 · 纯浏览器运行          │
│ contracts/golden（5 契约）    │          │ （golden 公式 JS 移植对拍）    │
└──────────────────────────────┘          └──────────────────────────────┘
```

核心演进方向：**从「C# 多服务 + 本地算法」演进为「纯前端单文件 + AI 深度参与 + 受约束智能体」**，把后端能力（构图增强、出题、计划编排、文本清洗）通过大模型接入层下沉到浏览器内完成，并保留「数字只由本地公式计算」的可解释性约束。
