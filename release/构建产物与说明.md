## 二、构建方案概述

仓库已有成熟的三端同构打包链，**本次全部复用既有工程，未新建桌面/安卓壳、未引入任何新依赖**：

1. **前端/UI 单一事实来源**：`deploy\monolith-web\index.html`（77,922 字节）——无服务器单体版页面，全部业务逻辑（起步/藏书阁/识网/知债/今日/智能体/画像/账户）在页面内完成，数据存 localStorage。
2. **Windows 端**：`src\AstralPath.Monolith` —— .NET 10 WinForms + WebView2 壳（`net10.0-windows`，自包含 `win-x64`），通过 `file://` 加载同目录 `Resources\index.html`；用 Inno Setup 7 的 `setup-monolith.iss` 打成 exe 安装包。
3. **Android 端**：`src\AstralPath.Native` —— Gradle（Kotlin DSL）WebView 壳工程（AGP 9.0.0，`com.astralpath.app.v22`，minSdk 26 / targetSdk 35，versionCode 32 / versionName 2.2.0），通过 `WebViewAssetLoader` 加载 `assets/www/index.html` 并注入离线模式标记；工程自带 release 签名配置（`astralpath-release.keystore`），`assembleRelease` 直接产出已签名 APK。

**两端一致性核心**：构建前把 `deploy\monolith-web\index.html` 同步刷新到 Windows 壳的 `Resources\` 与 Android 壳的 `assets\www\`，三份文件 SHA256 完全一致（见第六节），因此 UI 与功能逐字节同源。

## 六、两端如何保持 UI 与功能一致

1. **同一份前端**：Windows 壳（WebView2 加载 `Resources\index.html`）、Android 壳（`WebViewAssetLoader` 加载 `assets\www\index.html`）、Web 版（`deploy\monolith-web\index.html`）使用同一文件。构建前后三次哈希校验：
   ```
   deploy\monolith-web\index.html                                  4C0AB32E1178E501C9EB929DCDCB16EB196B623FE2E642A94DF900C67ED01DD7
   src\AstralPath.Monolith\Resources\index.html                     4C0AB32E...（同上）
   src\AstralPath.Native\app\src\main\assets\www\index.html         4C0AB32E...（同上）
   ```
2. **同一 API 语义**：两端都不指向远程后端——单体版整页为本地计算（localStorage 持久化、可导出 JSON）。Android 端 `MainActivity.injectOffline()` 仅注入 `window.__ASTRALPATH_OFFLINE__=true` 标记让前端走离线核心，不改任何 UI；Windows 端直接 `file://` 加载。因此**两端 UI、交互、功能完全一致，且均无后端依赖**。
3. **壳只做容器**：两端壳（WebView2 / Android WebView）只负责窗口、硬件加速、DOM 存储开启等容器级行为，业务逻辑 100% 来自同一 HTML。

## 九、遇到的问题与解决

1. **NuGet 崩溃：`Value cannot be null. (Parameter 'path1')`**
   - 现象：`dotnet restore` / `dotnet publish` / `dotnet nuget list source` 全部失败，连仓库外的新建空工程也失败，排除仓库配置问题。
   - 根因：远程执行 shell 的进程环境缺失 `ProgramFiles` / `ProgramFiles(x86)` 环境变量，NuGet `ConfigurationDefaults` 静态初始化时 `Path.Combine(null, ...)` 抛异常。本机用户自己的终端不受影响（当天 11:41 的历史构建即由用户终端完成）。
   - 解决：在脚本环境中显式注入这两个变量后一切正常。该补丁已写入 `release\build-release.ps1`，今后在任何受限 shell/CI 里跑构建都不会再踩。
2. **构建命令超过远程 shell 120 秒上限**：首次前台执行 `gradle assembleRelease` 超时被杀。解决：改用 `Start-Process` 后台启动 + 输出重定向到 `C:\Temp\ap-build\build.out`，轮询日志确认 `BUILD SUCCESSFUL in 11s`。（期间一次 `cmd /c ... > log` 的重定向因参数引用问题产生空日志，换用 `Start-Process -RedirectStandardOutput` 后正常。）
3. **MSB3277 / Gradle deprecation 警告**：均为良性提示（WindowsBase 版本统一、AGP 对 Gradle 10 的兼容预告），不影响产物，已如实记录。
